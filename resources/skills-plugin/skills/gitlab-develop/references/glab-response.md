# glab応答の判定と停止

`skills/gitlab-*`配下で`glab`を単独実行するブロックが、応答をどう判定し、いつ止まるかをここにまとめる。各skillはこのファイルへ参照を置き、判定の中身を複製しない。

## 失敗と判定する条件

次のいずれかに当たれば失敗として扱い、後続の手順へ進まない。

- 終了コードが非0
- stdoutが0バイト (空文字列)
- 出力が`{"message": ...}`・`{"error": ...}`の形のJSON (例: `{"message":"404 Not Found"}`)
- `401`・`403`、または`glab auth login`を促す認証エラーの文字列
- 読むべきフィールドが出力に無い (キー自体が欠けている、または値が`null`)

`[]` (空配列) は正常な0件であり、上記の失敗には当たらない。0件のときに次のフェーズへ進むか止まるかは、各ブロックの指示に従う。同様に、値が`null`になり得ることを呼び出し元が明記し、`null`の場合の動きを個別に定めているフィールド (`approvals_left`、`head_pipeline`など) は、そのフィールドに限り呼び出し元の指示を優先する。

## 書き込み系 (POST/PUT/note作成) の成功判定

返ったJSONに、作成・更新された対象の`id`などが載っているかで判定する。載っていなければ失敗として扱う。POSTは自動で再試行しない (再試行するとnoteやwikiページが重複して作られる)。

## 停止時の動き

失敗と判定したら、後続の手順へ進まない。実行したコマンド・終了コード・生ログ (stdoutとstderrの全文) をそのままユーザーへ示して止まる。推測した値で補って先へ進まない。
