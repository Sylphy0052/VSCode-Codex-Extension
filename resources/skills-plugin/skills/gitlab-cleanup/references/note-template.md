# 完了記録noteのテンプレート

close-and-delete.mdのフェーズ3から参照される (SKILL.mdから参照)。Issueをクローズする前に投稿する。

## 何のために書くか

**Issueを見た人が、MRを開かずに何が起きたかを追える**ようにする。Issueは着手前の状態と試行錯誤を持ち、MRは結果を持つ。完了記録は両者を結ぶ最後の1枚で、「このIssueはどう決着したか」だけを短く残す。

Issue本文の`## 実装後追記` (試したこと、想定との差、調査で分かったこと) があれば、それは実装中に埋めてある。**完了記録でそれを繰り返さない**。

## テンプレート

以下は日本語の例。noteの言語はリポジトリ規約に従い、定めが無ければ利用者との会話の言語で書く。見出しを訳す場合も、固定の2種類 (完了 / 完了 (一部未達) に相当するもの) に揃える。

```markdown
## 完了

MR !<MRのIID> で `main` (`<マージコミット>`) へ反映した。

**やったこと**: (何が変わったか。2〜3行。利用者への影響が無い変更なら開発者から見た変化)

**主なコミット**
- `<hash>` (何をしたか)

**検証**: (受入基準をどう確かめたか。コマンドと結果、または目視確認の結果)

**残っている作業**: (無ければこの行ごと省く)
```

## 未達がある場合

タイトルを変え、何が未達で、どこへ持ち越したかを書く。

```markdown
## 完了 (一部未達)

MR !<MRのIID> で `main` (`<マージコミット>`) へ反映した。

**やったこと**: ...

**主なコミット**
- `<hash>` (何をしたか)

**未達の受入基準**: (どの基準が、なぜ満たせなかったか)

**持ち越し先**: #<IID> / (別Issueを立てていないなら、いつ判断するか)
```

**「だいたい終わった」で閉じない**。未達を残して閉じるなら、持ち越し先を必ず書く。書けないなら閉じるのが早い。

## 書き方

- 見出しは`## 完了`または`## 完了 (一部未達)`に固定する。あとから機械的に拾えるようにするため
- コミットハッシュは短縮形 (7桁) をバッククォートで囲む
- MRは`!<IID>`、Issueは`#<IID>`で書く。GitLabが自動でリンクにする
- 絵文字を使わない

## 統合MRで複数Issueをまとめて閉じる場合

Issueごとに、**そのIssueの分だけ**を書く。統合MR全体の説明を各Issueへコピーしない。読み手が知りたいのは「自分が見ているこのIssueがどうなったか」だけ。

主なコミットも、そのIssueに対応するものだけを挙げる。
