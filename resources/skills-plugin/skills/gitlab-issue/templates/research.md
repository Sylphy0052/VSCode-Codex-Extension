# researchテンプレート

調査・技術選定に使う。実装しないため、受入基準は「調査が終わったと言える条件」になる。

見出しはfeature/bugと揃えてある。以下をコピーして埋める。

```markdown
**種別**: research

## 概要

**現状**: (今何が分かっていないか。分からないことで何が止まっているか)

**何を調べるか**: (1〜2行)

**なぜ調べるか**: (この調査で何を決めたいのか。1〜2行)

**影響範囲**: (この調査結果が何を左右するか。1行)

## 詳細

### 調査項目

- [ ] ...

### 評価軸

比較する観点 (性能・保守性・コスト等) と、それぞれの重み。

### 制約

調査に使える時間、試せない選択肢など。

## 確認点

### 受入基準

- [ ] 評価軸すべてについて結論が出ている
  - 検証: (目視確認) 評価軸の各項目に結論が書かれているか
  - 期待: 未記入の軸が無い
- [ ] 採用案と不採用案の理由が書かれている
  - 検証: (目視確認) 不採用案それぞれに理由があるか
  - 期待: 理由の無い不採用案が無い
- [ ] 次に起票すべきIssueが特定できている
  - 検証: (目視確認) 次アクションが具体的なIssue候補になっているか
  - 期待: 「引き続き検討」のような曖昧な記述が無い

### 確認手順

## 実装後追記

調査中に随時追記する。

### 試したこと

| 調べたこと     | 分かったこと | 評価軸への反映 |
| -------------- | ------------ | -------------- |
| (調査後に記載) |              |                |

### 結論と根拠

### 次アクション
```

## research固有の注意

受入基準が目視確認ばかりになるのは種別の性質上やむを得ない。調査の成果は文章であり、機械検証できるものが少ない。

ただし**「調査した」を完了条件にしない**。何が決まれば終わりかを書く。決まらないまま終わる調査は、次に同じ調査を繰り返すことになる。
