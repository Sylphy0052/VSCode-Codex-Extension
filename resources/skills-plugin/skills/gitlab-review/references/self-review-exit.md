# 自己レビューの終了判定 (3巡上限・非常ブレーキ)

[self-review.md](self-review.md) の「終わりの決め方」から分離した節。自己レビューの並列4agentの巡を、何巡まで回し、どの条件で終えるかを定める。

条件の既定は次のとおり。自己レビューは最大3巡、他者レビューは最大1巡で、「指摘が0件になるまで」を停止条件にしない。severityは `critical` / `high` / `medium` / `low` の4段階で、`critical` / `high` / `medium` は直す。巡の上限を過ぎても `medium` 以上が残る間は修正を続け、マージしない。見送った `low` が1件以上残るなら、MRごとに1件のIssueへ切り出してから自己マージする。リポジトリの `CLAUDE.md` / `AGENTS.md` に自己マージやレビュー巡数の定めがあれば、そちらを優先する。ただし「`critical` / `high` / `medium` が0件」の条件はrepo側の記載でも外さない。

**上限は3巡**。次の2つが揃えば3巡を待たずに終わる。

1. `critical` / `high` / `medium` が0件 (すべて直した)
2. 最後の巡で新たに直した差分が無い

指摘を直したら、直した差分に対してもう1巡回す。修正が新しい問題を持ち込むことがある。**ただし通算3巡を超えない**。3巡目で直した差分は、もう1巡回す代わりに自分で読み直して確かめる。

**3巡を過ぎても `medium` 以上が残る間は、修正を続けてレビュー依頼へ進まない**。巡の上限は4並列レビューを回す回数の上限で、直す作業の打ち切りではない。4巡目以降は4並列を回さず、残った指摘を直して自分で読み直す。次のどれかに当たり、修正で解消できないと判断したときだけ、ユーザーへ状況を提示して止まる。

- 直すにはこのMRのスコープ外の変更が要る
- 直し方がユーザーの判断に依存する (仕様の選択、互換性を壊すかどうか)
- 同じ指摘を2回直しても、形を変えて再び出る
- 3巡を過ぎてから修正を3回重ねても、`medium` 以上が残る (理由を問わない非常ブレーキ)

4巡目以降の修正は巡に数えないが、修正のたびに「残っていた指摘と直した内容」をnoteへ1件ずつ残す。記録が無いと、上の「2回直しても」「3回重ねても」を数えられない。

見送った `low` が1件以上残るときは、MRごとに1件のIssueへ切り出してからレビュー依頼へ進む。未対応の指摘が0件なら切り出さない。切り出す対象は、直近のnoteの「見送り一覧 (累積)」節 ([mr-template.md](../../gitlab-develop/references/mr-template.md)) のうち状態が `見送り (low、別Issue予定)` の行とする。切り出したら該当行の状態を `見送り (low、#<IID>へ切り出し済み)` へ更新する。

### 切り出し漏れの機械検査

レビュー依頼へ進む直前と、自己マージの直前 ([merge.md](merge.md) の「自己マージ」) に、最後に投稿した自己レビューnoteのファイルを検査スクリプトへ渡す。状態を更新したnoteを投稿し直した場合は、その更新後のファイルを渡す。

```bash
python3 "<このskillのベースディレクトリ>/scripts/check_deferred_low.py" /path/to/note.md
```

スクリプトはファイル内の最後の「見送り一覧 (累積)」節だけを読み、各行の状態を判定する。出力と終了コードは次のとおり。

| 終了コード | 意味                                               | 出力                                                                    | 次の手順                                                                                                                   |
| ---------- | -------------------------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 0          | 切り出し未了の行が無い (一覧が `N/A` の場合を含む) | `結果:` の集計行だけ                                                    | 先へ進む                                                                                                                   |
| 1          | 切り出し未了の行、または状態を判定できない行がある | `未切り出し:` / `状態不明:` で始まる行を1件1行、最後に `結果:` の集計行 | `未切り出し:` の行をIssueへ切り出して状態を更新する。`状態不明:` の行は状態を3種類のいずれかに直す。直したnoteで再実行する |
| 2          | 入力を読めない、または節が無い                     | 標準エラーに理由                                                        | 渡したファイルを確かめる。自己レビューnoteには見送りが無くても節 (`N/A`) を書く                                            |

投稿に使ったファイルが手元に無いとき (`/clear` の後など) は、MRのnoteを投稿日時の新しい順で取り、`## self-review` で始まり「見送り一覧 (累積)」節を持つnoteのうち `created_at` が最も新しいものを検査する。`glab mr note list` の出力を丸ごと渡すと、並び順によっては最新でないnoteを検査するため使わない。

```bash
glab api "projects/:id/merge_requests/$IID/notes?sort=desc&order_by=created_at&per_page=100" \
  | jq -r '[.[] | select((.body | startswith("## self-review")) and (.body | test("(^|\\n)[ \\t]*###[ \\t]+見送り一覧[ \\t]*\\(累積\\)[ \\t]*(\\n|$)")))]
           | sort_by(.created_at) | last | .body // empty' \
  | python3 "<このskillのベースディレクトリ>/scripts/check_deferred_low.py" -
```

該当するnoteが無いときは入力が空になり、終了コード2で止まる。見出しの前後の半角スペース・タブは、スクリプトと同じく許す (全角スペース等は対象外)。見出しは1行に収まったものだけを対象とし、「###」と「見送り一覧」が改行で分かれている場合はスクリプトと同じくどちらも選ばない。

パイプやリダイレクトを使えない環境 (glabを単独でしか実行できないsandboxなど) では、次の手順で検査する。

1. note一覧を取る。`glab api "projects/:id/merge_requests/$IID/notes?sort=desc&order_by=created_at&per_page=100"` を単独で実行し、出力のJSON配列を読む
2. 検査するnoteを選ぶ。`body` が `## self-review` で始まり、行頭 (前後に空白があってもよい) に1行で `### 見送り一覧 (累積)` の見出しを持つnoteのうち、`created_at` が最も新しいものを選ぶ。手順1の出力は新しい順に並ぶため、先頭から見て最初に条件を満たしたnoteが該当する。手順1の出力にすでに選んだnoteの `body` が含まれるため、手順3で同じnoteを取り直さない
3. 本文をファイルへ保存する。`body` の値はJSON文字列としてエスケープされている。先頭から1文字ずつ走査し、`\"`→`"`、`\\`→`\`、`\/`→`/`、`\n`→改行、`\t`→タブ、`\r`→復帰、`\b`→バックスペース、`\f`→改頁、`\uXXXX`→対応する文字 (サロゲートペア `\uD800`〜`\uDFFF` は2つ1組で1文字に結合する) のように出現したエスケープをその場で解いた本文を、Writeツールで `$TMPDIR/self-review-note.md` などへ書き出す。`\\` をまとめて先に置換すると、直後に続く `\n` 等を二重に解釈するため、置換は先頭からの一度きりの走査で行う。glabの出力をリダイレクトできないため、シェルでは保存しない
4. 保存したファイルを `check_deferred_low.py` へ渡す

**巡が伸びる構造を避ける**。文書を多く含むMRでは、レビューは毎巡かならず何かを出す。上限を置いただけでは、上限まで毎回回ることになる。次の3つで指摘の湧き出しを止める。

- **2巡目以降は対象範囲を絞る** ([self-review.md](self-review.md)の「巡ごとの対象範囲」)。前の巡以降に直した差分・前の巡の指摘・その影響範囲だけを見る。公開インターフェース・権限・フロー定義が変わった巡は例外として網羅範囲で見る
- **見送りと決めたものは「再指摘は不要」としてagentのプロンプトへ書く**。同じ見送り (テストの追加、別Issue送りと決めた項目) を毎巡指摘させない
- **直した差分は、次の巡へ出す前に自分で1回読む**。修正そのものが次の巡の指摘源になる

**`medium` は黙って見送らない**。直せない `medium` が出たら、上の「修正で解消できない」に当たるかを判断し、当たるならユーザーへ提示して止まる。自分の判断だけで見送ってレビュー依頼へ進まない。
