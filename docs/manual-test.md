# 実機確認手順

実VSCodeでしか確認できない範囲のチェックリスト。ロジック層はユニットテスト（`npm test`）が担うため、ここでは**実際のCLIプロセス・Webview・タブ復元**が絡む挙動だけを対象にする。

対象CLI: Codex CLI 0.147.0 / Claude Code 2.1.226（確認時の版を各回の記録に残す）。

## 進め方

1. 下の「準備」を済ませる
2. ケースを上から順に実行する。C群（Codex画面・16件）→ L群（Claude Code画面・11件）→ P群（ループ実行・5件）→ H群（履歴・復元・8件）→ A群（作業記録・4件）
3. 各ケースの結果を「記録テンプレート」に写す。落ちたものはIssue化してから次へ進む

前提が崩れるケース（C-01・L-01）が落ちた場合、その群の残りは実行しても意味がないので中断して原因を先に潰す。

## 準備

```bash
npm run check     # 全緑であること
npm run build     # dist/extension.js を更新
```

- VSCodeで `F5`（Run Extension）。拡張機能ホストの新しいウィンドウが開く
- 開発ホスト側で確認用の作業フォルダを1つ開く。**ファイルを壊してよい捨てフォルダ**にする（承認の確認でコマンドを実際に実行させるため）
- コマンドパレット → `Agent: ログを表示`（`codex.showLog`）でOutputChannelを常時開いておく。以下「ログ」と書いたらこれを指す
- WSL Remoteの場合、拡張機能は `extensionKind: ["workspace"]` でリモート側に載る。CLIがリモート側のPATHにあることを `which codex` `which claude` で確認する

### 設定

承認カードを確実に出すため、確認中は次にする（`settings.json` またはサイドバーの設定パネル）。

| キー                        | 値                 | 理由                                 |
| --------------------------- | ------------------ | ------------------------------------ |
| `codex.sandbox`             | `read-only`        | 書き込みのたびに承認要求を発生させる |
| `codex.approvalMode`        | `on-request`       | 承認カードの経路を通す               |
| `claude.permissionMode`     | 空 または `manual` | control protocolの承認を通す         |
| `agent.activityLog.enabled` | `true`             | A群で使う                            |

`codex.approvalMode` が `never` だと承認要求そのものが発生せず、サンドボックスで弾かれた操作がそのまま失敗する。`danger-full-access` + `never` の組み合わせ、および `claude.permissionMode` の `bypassPermissions` も承認カードが出なくなるため、C群・L群の承認ケースでは使わない。`workspace-write` では作業フォルダ内の書き込みが承認なしで通るため、承認カードの確認には向かない。

**前提**: サンドボックスの実行には `bubblewrap` が要る。無いと `Codex could not find bubblewrap on PATH` が出てサンドボックス実行が失敗し、承認要求の内容が「サンドボックス無しで再試行するか」という異常系に変わる。

```bash
sudo apt install bubblewrap
```

## C群: Codex画面（app-server）

未確認領域の中心。`codex app-server` との接続・承認・分岐・タブ名が対象。

### C-01 画面が開いて発言が返る

- 操作: サイドバーの `+` アイコン（`codex.newChat`）
- 期待: エディタタブとしてCodex画面が開く。`こんにちは` と送ると、応答が**逐次流れて**表示される（`item/agentMessage/delta` によるストリーミング）
- 確認: ログに接続エラーが出ていない。応答が一括ではなく徐々に伸びる
- 落ちたとき: `codex app-server` が起動できているか、ログのstderrを見る。ここが落ちたらC群は中断

### C-02 使用量と状態表示

- 操作: C-01の続き
- 期待:
  - ステータスバーに `Codex <n>%` が出る。クリック（`codex.showUsage`）で内訳が出る
  - Codex画面のフッターに `使用量 <n>%` が出る（`account/rateLimits/updated` 由来）
- 確認: ホバーでプラン・リセット時刻・時点が出る。トークン数は表示しない仕様

### C-03 承認カード（許可）

- 操作: 「`test.txt` というファイルを作って」と指示する
- 期待: 画面内に承認カードが出て、**Codexが応答待ちで止まる**。「許可」を押すとコマンドが実行され、会話が再開する
- 確認: 実際に `test.txt` ができている。カードが消えて会話が続く

### C-04 承認カード（拒否）

- 操作: 同様に書き込みを指示し、カードで「拒否」を押す
- 期待: 実行されず、その旨が会話に反映されて次のターンへ進める（画面が固まらない）

### C-05 承認カード（このセッションでは許可）

- 操作: 「この会話では常に許可」（`acceptForSession`）を選び、続けて**まったく同じコマンド**を指示する（例: どちらも `touch same.txt`）
- 期待: 2回目は承認カードが出ずに実行される
- 注意: 記憶されるのは**コマンド単位**。`touch a.txt` を許可しても `touch b.txt` では再び聞かれる（app-serverへ直接問い合わせて確認済み）。引数違いで試すと「効いていない」ように見える

### C-06 保留中の承認を残したままタブを閉じる

- 操作: 承認カードが出ている状態でCodex画面のタブを閉じる
- 期待: 保留中の要求が `cancel` で解放される。ログに解放の記録があり、app-serverが待ち続けない
- 確認: 別のCodex画面を開いて発言できる（プロセスが詰まっていない）

### C-07 中断

- 操作: 長めの作業を指示し、応答中に「中断」ボタンを押す。`Esc` でも同じことができる
- 期待: `turn/interrupt` が飛び、**その場で**応答が止まる。その後に続けて発言できる
- 確認: 中断後に文字が流れ続けないこと（turnIdを渡せていないと要求が失敗し、止まらないまま最後まで流れる）

### C-08 タブ名の自動追従

- 操作: C-01の会話を数ターン進める
- 期待: Codexが要約名を付けた時点（`thread/name/updated`）でエディタタブの名前が変わる

### C-09 セッション名の変更

- 操作: Codex画面がアクティブな状態でエディタ右上の鉛筆アイコン（`codex.renameChat`）→ 新しい名前を入力
- 期待: タブ名が変わる。**サイドバーの履歴一覧の表示名も変わる**（`thread/name/set` はCodex側に永続化される）
- 確認: 履歴を更新（`codex.refreshSessions`）しても新しい名前のまま

### C-10 会話の途中から分岐

- 操作: 会話を3ターン以上進め、途中の**自分の発言**にある「ここから分岐」を押す（ボタンは人の発言にだけ出る）
- 期待: 新しいCodex画面のタブが開き、**押した指示の手前まで**の会話を引き継いでいる。その指示からやり直せる状態になる。元のタブは無傷で残る
- 確認: 分岐先で発言しても分岐元には影響しない。1つめの発言には分岐ボタンが出ない（引き継ぐ手前が無いため）

### C-11 タブ復元

- 操作: Codex画面を2枚開いた状態でウィンドウをリロード（`Developer: Reload Window`）
- 期待: 両方のタブが会話内容つきで復元される（`registerWebviewPanelSerializer` → `thread/resume`）
- 確認: 復元後にそのまま発言を続けられる
- 注意: **中断したターンの応答は戻らない**。Codexが自分の発言しか保存しないため（設計書 §9.6）。中断を試した直後に確認すると、消えたように見えて紛らわしい

### C-12 履歴から開く

- 操作: サイドバーの履歴の項目をクリックする（`codex.openSession` → チャット画面へ）
- 期待: 過去のセッションがチャット画面で開き、過去のやり取りが表示された状態から続けられる
- 確認: 既に開いているセッションなら、二重に開かずそのタブが前面に来る
- 確認: ホバーの吹き出しアイコン（`codex.openChat` / `claude.openChat`）でも同じ画面が開く

### C-13 応答中の指示は待ち行列に積まれる

- 操作: 長めの作業を指示し、応答中にさらに2件送る
- 期待: 「応答が終わってから送ります（2件）」と一覧に出る。ターンが終わると1件目が自動で送られ、その次も順に送られる
- 確認: 待機中の項目を「取り消す」で個別に消せる。「今すぐ送る」を押すと応答を中断して先頭の1件が送られる

### C-14 スラッシュコマンドの候補

- 操作: 入力欄で `/` を打つ
- 期待: 候補が一覧で出る。組込（`/review` `/compact` など）が先、`~/.codex/prompts/*.md` のカスタムが続く
- 確認: 文字を足すと絞り込まれる。`↑` `↓` で選び、`Tab` か `Enter` で入力欄に入る（送信はされない）。`Esc` で閉じる
- 確認: 行の途中で `/` を打っても候補は出ない（パスを書くときに邪魔しないため）

### C-15 入力欄の履歴

- 操作: 3回以上発言したあと、入力欄が空の状態で `↑` を押す
- 期待: 直前の発言が入力欄に出る。続けて `↑` でさらに前へ、`↓` で新しい方へ戻る。最新まで戻ると入力中だった内容が復元される
- 確認: 複数行を入力した状態では、2行目以降の `↑` が通常のカーソル移動になる（履歴に切り替わらない）

### C-16 履歴から会話を読んで分岐

- 操作: Codexのセッションにホバー → ブランチアイコン（`codex.openConversation`）
- 期待: 会話ビューアが開き、過去のターンが並ぶ。ターンを選ぶとそこから分岐した新しいチャット画面が開く
- 確認: 分岐できる指示が無いセッションでは「分岐できる指示がまだありません」と出る

## L群: Claude Code画面（stream-json）

`--print --input-format stream-json` の常駐プロセスと control protocol が対象。

### L-01 画面が開いて発言が返る

- 操作: サイドバーのスパークルアイコン（`claude.newChat`）
- 期待: Claude Code画面が開き、応答が逐次表示される（`--include-partial-messages`）
- 確認: ログに起動失敗が出ていない。ここが落ちたらL群は中断

### L-02 承認ハンドシェイク

- 操作: L-01の起動直後
- 期待: `{"subtype":"initialize"}` に `control_response/success` が返る。**警告通知が出ない**
- 落ちたとき: `この画面ではツール実行の承認を受け取れませんでした。claude.permissionMode の設定に従って動作します。` が1度だけ出る。会話自体は続けられること（通知が出る＝ハンドシェイク失敗。CLI側の版差を疑う）

### L-03 承認カード（許可 / 拒否）

- 操作: ファイル書き込みを指示する
- 期待: `can_use_tool` を受けて承認カードが出る。「許可」で実行、「拒否」で実行されずに会話が続く
- 確認: `acceptForSession` を選んだ場合も許可として通る（CLI側に区別が無いため2回目も出る想定）

### L-04 承認無効の警告

- 操作: `claude.permissionMode` を `bypassPermissions` にして新しいClaude Code画面を開く
- 期待: モーダルで `承認が無効になっています。Claude Code はツールを確認なしで実行します。` が出て、「実行する」を押すまで進まない
- 後始末: 確認後は設定を戻す

### L-05 中断

- 操作: 長めの作業を指示し、応答中に「中断」ボタン
- 期待: control protocol の `interrupt` が飛び、応答が止まる。続けて発言できる

### L-06 セッションIDの紐付け

- 操作: L-01のセッションを1ターン進める
- 期待: `~/.claude/projects/<cwd-slug>/<sessionId>.jsonl` に、起動時に指定したUUIDと同名のtranscriptができている
- 確認: `ls -t ~/.claude/projects/*/ | head` で直近のファイル名を見る

### L-07 履歴の表示名

- 操作: サイドバーの履歴を見る
- 期待: L-01のセッションが**最初の人の発言**から作った名前で並んでいる。subagentの発言やツール結果、IDEが挿入する制御タグが名前になっていない

### L-08 resume の初期表示

- 操作: 履歴からL-01のセッションをClaude Code画面で開く（`claude.openChat`）
- 期待: 過去のやり取りが表示される（`--resume` は標準出力に流さないため、transcript読み込みで作る経路）
- 確認: そのまま続きを発言できる

### L-09 タブ復元

- 操作: Claude Code画面を開いた状態でウィンドウをリロード
- 期待: タブが会話内容つきで復元され、続けて発言できる

### L-10 fork（idが未確定になること）

- 操作: 履歴からClaude Codeセッションをforkする
- 期待: 新しいタブが開いて会話は継続できるが、**そのタブは復元と作業記録の対象外**になる（CLIが振る新しいidを追跡できないため）
- 確認: リロード後にそのタブが復元されないことが期待動作であること

### L-11 使用量の表示

- 操作: L-01の会話を1ターン進める
- 期待: 画面フッターに `5時間制限 リセット <n>時間後` のように出る（`rate_limit_event` 由来）
- 期待: ターンが終わるとステータスバーに `Claude <n>%` が出る（`claude --print /usage` を別プロセスで叩いて読む。60秒は叩き直さない）
- 確認: 制限に到達している場合は `到達` が併記される

## P群: ループ実行

チャット画面のループパネル。CodexとClaude Codeで同じ制御を使うため、P-01〜P-04はCodex画面、P-05はClaude Code画面で確認する。

### P-01 回数で止まる

- 操作: 「ループ」ボタン → 初回指示 `1と書いてください`、継続指示 `次の数字を書いてください`、最大回数 `3`、終了条件は空 → 「ループ開始」
- 期待: 指示が自動で3回送られ、3回目のターンが終わると `ループ終了（3/3回目）・指定した回数を送り終えました` が出る
- 確認: 進行中は `ループ 2/3回目` のように表示が進み、「ループ停止」ボタンが出ている

### P-02 終了条件で止まる

- 操作: 継続指示 `次の数字を書いてください`、最大回数 `20`、終了条件 `5まで書き終えている` で開始
- 期待: 5に達したターンで `ループ終了（n/20回目）・条件が成立しました` になり、回数を残したまま止まる
- 確認: 送られた指示に終了条件の依頼文が添えられている（会話ログのユーザー発言で見える）

### P-03 手動の割り込みで止まる

- 操作: P-01と同じ設定で開始し、1回目の応答が終わった直後に入力欄から手で発言する（または `Esc` で中断する）
- 期待: `ループ終了（n/3回目）・手動の操作が入ったため止めました` になり、以降は自動送信されない

### P-04 承認待ちで進まない

- 操作: 承認が出る設定（準備の「設定」）で、継続指示にコマンド実行を含むものを指定して開始し、承認カードが出た状態で放置する
- 期待: 承認カードが出ている間は次の指示が送られない。許可するとそのターンが終わってから次へ進む

### P-05 Claude Code画面でも同じに動く

- 操作: Claude Code画面でP-01と同じ設定を実行する
- 期待: 同じ表示・同じ止まり方になる
- 確認: 途中でCLIプロセスが落ちた場合は `応答が失敗したため止めました` になる

### H-06 コマンドパレットからの再開

- 操作: `Agent: セッションを再開…`（`codex.resumeSession`）
- 期待: QuickPickに一覧が出る。プロバイダ名と相対時刻が添えられ、選ぶとチャット画面で開く
- 操作: `Agent: 直前のセッションを再開`（`codex.resumeLast`）
- 期待: 一覧の先頭がそのまま開く。セッションが無ければその旨が出る

### H-07 外部変更の追従

- 操作: 別のターミナルでCLIから直接セッションを作る / archiveする
- 期待: ファイル監視でTreeViewが追従する。開いているタブはそのまま残る（既知の制約）

## 記録テンプレート
