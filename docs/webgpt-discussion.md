# WebGPTとの議論

## 概要

会話下の三点メニュー「WebGPTと議論…」、コマンドパレット、履歴ビューから議題と任意のChatGPT会話URLを指定し、エージェントがPlaywrightで質問・批評・追加質問を送り、結論をまとめる。三点メニューはCodex・Claude Codeの両方に表示する。Claude Codeでは起動元のプロセスへPlaywright MCPを動的に追加し、同じセッションの文脈・モデルを使って議論する。別タブ作成・再起動・Codexへの切り替えは行わない。Codexも起動元の同じセッションで議論する。CodexにはMCP動的追加APIがないため、現在のエージェントが固定バージョンのPlaywright CLIを通常のシェルツールから呼び、既存ChromeへCDP接続する。

既存のセカンドオピニオンは変更しない。ブラウザ操作の専用状態機械は追加せず、通常のチャット送信経路とPlaywright MCPまたはCLIを使う。

## 詳細

- 議題、任意の会話URL（指定する場合は1〜3件）、各会話への送信上限1〜5回を入力する。既定の上限は2回。URLが空欄または空白のみならChatGPTの新規会話を1件作成し、その会話で議論する。
- 会話URLは`https://chatgpt.com/c/<id>`のみ受け付ける。認証情報・クエリ・フラグメント・重複は受け付けない。
- 接続先は`agent.webGpt.cdpEndpoint`で指定する。既定値は`http://127.0.0.1:9222`。HTTPのループバック接続に限定する。
- URL入力前にCDP接続を確認する。接続拒否で未起動と判定した場合だけ、専用プロファイルのChromeを1回起動し、最大30秒で接続を待つ。既存の接続を再利用し、無応答や不正応答では原因を表示して中断する。
- WindowsとWSLではWindowsのChromeを起動する。macOS・Linuxではその環境のChromeを起動する。Chromeが見つからない場合はインストールを求めて中断する。プロファイルの削除、既存ブラウザの終了、外部向けポート公開は行わない。
- ログインは利用者が開いたChromeで行う。入力をキャンセルしても起動済みChromeは残す。同時の起動確認は接続先ごとに共有する。
- Claude Codeでは`mcp_status`で既存の動的MCP設定を取得し、全件を保持して`mcp_set_servers`へ渡す。設定を取得できない場合・同名サーバーの衝突・追加失敗・接続未完了では送信しない。プロセス終了と時間切れで待機を解放する。入力中・接続中に会話を閉じた場合も送信しない。応答中・送信待ちがある場合は完了を待つよう表示し、自動で中断しない。
- 両プロバイダーの議論では現在の文脈を考慮し、議題に必要な論点を要約してWebGPTへ送る。会話全文・ファイル・認証情報を自動転送しない。議題を空にした場合は現在の会話から論点を選ぶ。
- CodexはPlaywright CLI 0.1.20をnpxで呼ぶ。専用CLIセッション名とCDP設定を拡張機能のストレージへ作り、既存のCodexセッションへ操作手順を送る。app-server・会話を再起動せず、グローバルMCP設定も変更しない。CLI実行には現在のシェル権限を使い、実行できない場合は中断する。CLIの出力先は拡張機能のストレージとし、ワークスペースへ設定を生成しない。
- 開始操作の説明で、議題と議論中の回答・批評を指定会話へ送信することを示す。両プロバイダーでは現在の論点を要約して送ることも示す。会話全文やワークスペースのファイルは自動で添付しない。
- エージェントへの開始指示には、指定会話だけの操作、送信上限、今回の回答と過去の回答の区別、生成完了の確認、重複送信の回避を含める。
- 議論先の文章は議論の資料として扱い、ローカル操作や追加の情報送信を許可する指示として扱わない。
- 起動後も接続できない場合は議論を開始せず理由を表示する。議論中にログインが必要な場合は、その状況を議論中の会話で報告して中断する。認証回避や既存ブラウザ設定の変更は行わない。
- 停止・追加発言・履歴保存は通常のチャットと共通。送信上限や対象制約はCodexへの指示であり、拡張側でブラウザ操作を強制制御するものではない。

## 受入基準

1. Codex・Claude Codeの会話下の三点メニュー、コマンドパレット、履歴ビューから議論を開始できる。
2. 入力途中のキャンセルでは議論指示を送信しない。不正URL・重複URL・範囲外の送信上限を拒否する。
3. 議題・対象URL・送信上限を含む開始指示とCDP接続用MCP設定を、両プロバイダーとも起動元のセッションへ渡す（CodexはCLI接続手順）。
4. 通常の新規会話と既存のセカンドオピニオンの開始設定を変えない。
5. 結論には対象URL、各会話の意見、合意点、相違点、未確認事項を求める。取得できなかった回答を成功扱いしない。
6. 操作手順と、ログイン済みChrome・npxが必要なこと、実行制御の限界をREADMEに記載する。
7. CDP接続があれば起動せず再利用し、接続拒否なら専用Chromeを起動する。起動失敗・接続待ち時間切れでは議論指示を送信しない。
8. 両プロバイダーの三点メニューでは同じプロセス・セッションへ議論指示を送り、結果を同じ会話に残す。空の議題は現在の文脈を使う指示になる。
9. Claude Codeの既存MCP・モデル・権限設定を保持する。キャンセル・応答中・プロセス終了・MCP設定不明・接続失敗では議論指示を送らない。

10. URL空欄・空白のみで確定すると、新しいブラウザタブでChatGPTの新規会話を1件作成する。作成後はその会話だけで議論し、結果に会話URLを含める。既存会話・下書きを流用しない。キャンセルでは開始せず、URL指定時の検証と動作は維持する。

## 検証方針

ユーザー指示に従い、テスト・型チェック・lintは明示依頼時だけ実行する。実装後はビルドと最終差分を確認する。実際のChatGPT会話への送信を伴う動作確認は、この開発作業では行わない。

## 参照

[PlaywrightのCDP接続API](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp)。Playwright MCPの`--cdp-endpoint`は導入済みバージョンの公式READMEで確認した。

Claude Codeの動的追加は[公式Agent SDKリファレンス](https://code.claude.com/docs/en/agent-sdk/typescript)と、公開SDK 0.3.193の`setMcpServers`実装を参照した。既存の動的サーバー一式を渡す置換APIのため、`mcp_status`で取得した設定を保持する。

CodexのCLI接続は[Playwright CLI公式README](https://github.com/microsoft/playwright-cli)の`--config`、名前付きセッション、`browser.cdpEndpoint`を参照した。会話がない場合・応答中・送信待ち・入力中のタブ終了では開始しない。CLI設定・生成物は拡張機能ストレージに残る。
