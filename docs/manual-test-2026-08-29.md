## U-43b-2 長い会話の要約 — OK

会話の1発言目に目的と制約4件を置き、`chatScript.ts` / `runner.ts` の引用で会話を膨らませた。

切り詰めの発火を数値で確認した。固定指示の長さは447文字 (`buildConversationSummaryPrompt('')` の実測)。

| 時点           | `promptChars`   | 会話部分    | 判定                  |
| -------------- | --------------- | ----------- | --------------------- |
| 手順1の時点    | 35,775 / 37,052 | 約35k / 36k | 未発火                |
| 膨らませた途中 | 114,016         | 113,569     | 未発火 (上限12万未満) |
| 到達後         | 120,529         | 120,082     | **発火**              |

120,082 の内訳は `head + tail` がちょうど 120,000 (`headChars = 24,000` / `tailChars = 96,000`) と、省略の注記2本と空行で82文字。`capConversationForSummary` の実装どおり。

この状態で「守るべき制約をすべて挙げ、いま検討している方針がそれを破っていないか確認して」と依頼したところ、**1発言目の目的と制約4件すべてに言及した回答**が返った。会話の先頭24,000文字が保持されている。

末尾も生きている。回答に「その後のコード引用依頼は実装権限を与えていない」とあり、会話後半の引用作業を指している。

旧実装 (末尾のみ12万文字を保持) であれば、会話が約13万文字ある状態で先頭1万文字が落ち、制約を挙げられなかったはずの条件。head+tailが実測で機能した。

なお回答が挙げた「違反」判定は、この確認のために作った架空の制約に対するもので、実在の受入基準ではない。

## 環境上の注意 (次回の再実施用)
