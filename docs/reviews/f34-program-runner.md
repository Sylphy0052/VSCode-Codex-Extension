## 指摘

### F34-01[P1]:起動処理待ちの全体停止が、残りrunの開始も待つ

[pumpProgram](../../src/orchestrator/programRunner.ts#L265)はプログラム単位の排他処理内で、起動候補を[順番に開始](../../src/orchestrator/programRunner.ts#L305)する。[全体停止](../../src/orchestrator/programRunner.ts#L349)も同じ排他処理へ入るため、[workflow.start待ち](../../src/orchestrator/programRunner.ts#L462)の途中に停止を要求しても、現在の起動と残り候補の起動が完了するまで停止フラグが立たない。

起動に時間のかかるrunがあると停止操作が遅れ、停止要求後も別のrunが開始される。排他処理の外で停止要求を記録し、各起動の前後で確認する必要がある。既に開始したrunの追跡と停止は排他処理内で整合させる。

確認例:独立したrunを2件用意し、1件目の開始待ち中に全体停止する。2件目が開始されないことと、1件目が停止対象に入ることを確認する。未実行。
