# 実行管理の寿命・承認試験とVSCodeモック

対象:test/unit/runnerDispose.test.ts、test/unit/runnerTaskApproval.test.ts、test/mocks/vscode.ts。全文の関数・分岐とテストの操作・期待値・片付けを確認した。テスト未実行。

## 破棄と再試行

runnerDisposeのgit fakeは2回目以降のworktree addをgateで停止する。破棄後の起動件数0、非破棄時の対照1件、初回host失敗からのretryを確認する。gate到達を別Promiseで待ち、停止位置を固定している点は単なる待機回数より強い。

「起動してしまったセッションが解放される」は同じworktree gateを使い、session配列をfor文で確認する。先行のガードが正常なら配列は空で期待値を1つも評価しない。host.openTaskSession自体を保留して、破棄後にsessionを返す条件はこの試験では検査できない。retry後の状態はfailedでないことだけで、runningとrunLoop開始まで検査しない。非破棄の対照・retryはrunnerを片付けない。identityFsは全パス存在・symlink無し、gitは固定成功、100回microtask待機であり、実worktreeの残留や除外設定は確認しない。

## 承認待ちの時間切れ

taskApprovalTimeoutSecの満了、満了前の承認/拒否、手動停止、依存タスクへの失敗伝播、承認待ちAと返信待ちB/Cが併存する場合の解除を確認する。60,000msちょうどでstopLoopを確認し、FakeTaskSession.finishを手動で発火して最終failureを観測する。実hostが停止からonFinishedまで確実に通知するかは対象外。timeout直前の未発火、同一時刻の承認との順序、複数request、遅れた旧requestの解決、dispose/復元/再試行を跨ぐtimerはこのファイルでは検査しない。

承認可否はresolveApprovalが直接callbackを呼ぶため、decideApprovalから通信応答までを通らない。stopLoopは常にtrue、interruptとpause/resumeは状態を変えない。返信待ち解除はstateがrunningになることまでで、実セッションのresumeや再送は観測しない。createHarnessのreadReplyTimeoutSec引数は渡しておらず、実際はmessaging deps側の値が使われる。afterEachは時計を戻すだけでrunnerを破棄しない。

## VSCodeモックの保証範囲

Emitterの購読/解除/走査時コピー/破棄、panelの生成/表示変更/二重破棄、configの直指定優先とドット階層、文書/設定/通知/コマンド/ステータスバー/ツリーの全メソッドと既定値を確認する。

postMessageは閉じたpanelでも必ずtrueで送信履歴を残し、実際の受理失敗やready前の消失を検査できない。panel.revealはactiveを変えるがvisibleをtrueへ戻さず、他panelのactiveも落とさない。dispose後にもreveal/受信を許し、Emitterもdispose後の再購読を禁止しない。resetはstateを空にするだけで既存panel/listener/timerや、試験が直接上書きしたwindow/workspaceメソッドを復元しない。

getWorkspaceFolderはURIを無視して先頭rootを返す。Uriはパスの正規化・encoding・scheme変換をしない。config updateはtargetを無視して同期反映し、設定変更イベントを出さない。直指定のドットキーがあるとnested updateより旧値が優先される。getNested/setNestedは継承プロパティも辿るため、設定解決の厳密な実物互換モックではない。

コマンドはIDだけを記録し引数と登録先を実行しない。ダイアログは既定で最初の選択肢を即承認し、入力検証/取消tokenを扱わない。writeFileはUTF-8化した記録のみで永続化しない。無題文書の編集値は全文書で共有する。activeTextEditorは編集APIを持たず、showTextDocumentはeditorを返さない。個別試験の上書きがない限り、これらの実挙動を通る検査と解釈しない。
