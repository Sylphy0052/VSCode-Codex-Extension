# 会話書き出しとファイル復元の精査

transcriptMarkdown、fileRewindと対応する2テストファイルを全文精査した。テスト・実ファイルの復元は実行していない。

| 対象                  | 関数・分岐・テスト内容と不足                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| transcriptMarkdown    | titleOf/headingOfのagent・既知/未知・detail/status/省略/中断、bodyOfの思考全文、diffBlocksの移動/種類、searchResultBlock、imageBlockの空/alt/path、renderItem、capTranscript、buildTranscriptMarkdown、defaultTranscriptFileNameを確認。テストは代表種別、全文優先、空会話・見出しだけ・順序、差分/移動/未知kind、検索リンク、画像path、巨大本文・2,000項目・日時を検査する。画像pathなし/空alt、Markdown記号入りtitle/URL/改行detail、フェンスを含むdiff、上限ちょうど、切断位置がフェンス内部の場合はない。上限は全量構築後に適用され、テストは応答時間・メモリーを計測していない。辞書の継承名も未知fallbackを通らない。 |
| fileRewind:読取り     | failure、checkedPathのrealpath・root/外部/.git/親symlink/特殊file/ENOENT/他error、readのfile/nlink/8MiB/UTF-8/NUL、reverseUpdateの不正diff・0行位置補正・失敗を確認。テストはroot外・親symlink・.gitを拒否するが、hardlink/サイズ/不正UTF-8/末端directory/権限エラーはない。検査と実際のopenは別で、同時の別processによる変更への原子的保証はない。                                                                                                                                                                                                                                                                         |
| fileRewind:記録・計画 | captureの重複ID、空changes/NUL、add/delete/update/未知、移動trailer・移動だけ・元残留・エラー記録、prepareの発言探索/除外status/逆順/欠落記録/前後連続性、copyを確認。テストは新旧2turn、同一fileの連続、空新規・末尾改行なし削除・編集移動、外部編集・不連続・欠落記録・declined・重複IDを検査。「未知の形式」名のテストは記録欠落のみ、「拒否・失敗」名のテストはdeclinedのみ。failed・未知kind・移動だけ・copyは直接確認しない。                                                                                                                                                                                         |
| fileRewind:適用・復旧 | validateのafter一致/親存在、applyの再検証/同値skip/成功/失敗と逆順復旧、writeの削除/既存w/新規wxを確認。テストは確認中の外部変更の保持、2回目write失敗で両fileを元のafterへ戻すことを確認する。unlink失敗、復旧自体の失敗、親消失、同値skip、移動後の復旧はない。モックはfinallyで実装を戻し、一時dirは毎テストafterEachで掃除する。重複captureのテスト補助はitemsも二重に追加するため、後像の上書き抑止以外の連続性エラーでも単なるtoThrowを満たしうる。                                                                                                                                                                   |

書き出しのMarkdownエスケープ不足と上限適用位置は契約上の注意として記録し、全入力の表示崩れや実測性能の問題が確認済みとはしない。復元の既存F09指摘も参照する。
