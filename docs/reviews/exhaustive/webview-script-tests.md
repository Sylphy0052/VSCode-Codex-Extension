## 検査している内容

- parsesはnew Functionで生成コードを構文解析する。関数本体は呼ばない。Codex/Claude、承認メタ、review導線、巻戻し・途中分岐、入力ヒント、送信キーの代表的組合せを確認する。
- chatScriptはフラグの埋込み、分岐対象ID、背景実行色、Markdown対象kind、各操作のメッセージ、メニュー位置、usage/debug/IME/履歴/トークン表示のコード断片を照合する。折畳み、状態色、種別アイコン、構文強調、コード操作、質問のその他入力も同じ方式。
- LoopStopReason、FileDiffKind、TaskFailureReason、TASK_STATES、ProgramRunSkipReason、importのkind、PluginProvidesは元の型宣言から正規表現で候補を抽出し、ラベル集合と比較する。空抽出への防御、型範囲、意図的な除外を確認。TaskFailureReasonは16件を固定する。
- KIND_LABELと書出しのKIND_TITLE、STATUS_LABELとSTATUS_CLASS、CLASS_OFと図案も集合で比較する。これは片方だけ更新する事故への検査であり、共通の誤字・誤表示までは検知しない。
- controlPanelは承認ラジオ、empty/error/loading共通処理、再試行の逆引き、開閉通知・保存・外部からの展開を確認する。旧classNameの検出正規表現には陽性対照がある。
- workflowは可視範囲、requestAnimationFrameの抑制、カンバン絞込み、進捗区画、状態色、矢印、ズーム、オーケストレーター入力、質問と配送待ち、再開可能理由、衝突解決バッジ、SVG幅計測とクリップを照合する。バッジは呼出し文脈3か所と定義込み4回を固定する。
- progressはファイル分類・打切り・展開記憶、ターン開閉・キャッシュ・フォーカス復元、稼働表示・読み上げ、テーマ色・固定位置・低減モーションの断片を確認する。

## 保証していない内容

- DOMを構築してクリック・入力・スクロール・状態更新を実行する試験ではない。イベント購読先が実在すること、送信した値、無効ボタン、入力保持、実測幅、表示順、フォーカス、読み上げ内容を検証していない。
- toContainで複数の文字列が存在しても、同じ関数内で到達可能な順番に実行される証拠にはならない。「append後に計測」「busy中は隠す」「同じ色を使う」などのテスト名が実際のassertionより強い場合がある。
- 一重引用符の行内偶奇、バッククォートや補間記号の不存在は限定的なソース規約。JavaScriptの正否一般を表さず、構文解析の代わりにはならない。innerHTML等の文字列不存在も、すべての注入経路の安全性を証明しない。
- 正規表現の型範囲は宣言の改行・インデント・一行表記に依存する。Set比較は重複を消す。各所の空抽出防御は確認したが、ASTに基づく型の全構造比較ではない。
- keyframesの検査は最初の閉じ括弧までで、後続キーフレームの禁止プロパティまでは見ない。.srOnlyのdisplay:none禁止も一つの表記のみを拒否する。CSS全体の算出結果は検査していない。

上記を試験不足として記録する。文字列試験があることを、全画面分岐の実行確認とは扱わない。
