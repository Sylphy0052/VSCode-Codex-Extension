## 指摘

### F40-01[P2]:評価集計が別runの結果を数え、試行数・失敗率を混ぜる

[評価実行](../../test/bench/secondOpinionEval/run.ts#L347)は既存の出力ディレクトリを使い、manifestを新しいrunIdで書き直す。一方、[集計の読込](../../test/bench/secondOpinionEval/summarize.ts#L235)は全JSONを結果として読み、record.runIdとmanifest.runIdを照合せず[試行・失敗数](../../test/bench/secondOpinionEval/summarize.ts#L254)へ加える。[入力固定の検証](../../test/bench/secondOpinionEval/recall.ts#L156)は案件と判定ファイルのハッシュだけを確認する。

同じ出力先で条件や試行回数を減らして再実行すると、今回上書きしなかった旧結果が集計へ混ざる。[採点シート](../../test/bench/secondOpinionEval/scoringSheet.ts#L157)は別runを除外するため、採点対象と集計の分母も一致しない。集計でもrunIdを照合し、必要なら条件・試行範囲と重複も検証する必要がある。

確認例:旧runの結果を1件残して別runを集計し、旧結果が試行数・失敗数へ入らないことを確認する。未実行。

## その他の確認

配布入口はpackage.jsonのpackageで、ビルド後に依存を同梱しないVSIXを作る。実行時依存はesbuildへ束ねる構成。.vscodeignoreはソース・テスト・docs・worktree・評価結果などを除外する。実際のVSIX内容は生成して確認していない。

単体検証はtest/unitへ限定する。統合fixtureは使い捨てプロファイル・専用ホームを用い、実CLIパスを存在しない値へ固定する。ワークフロー用のgit起点とremoteの隔離も検査する。外部CLI検証は別入口で、対象ファイル0件やプロセス起動失敗をエラーにする。

CIはcontents:readで、単体検証・ビルドと固定版Codexによる外部CLI検証を分ける。VSCode統合検証はCI対象外。ローカルcheckはlint・整形・型・単体検証で、CIのビルド・カバレッジと完全には同じでない。

進捗ベンチマークは合成データの全量と差分を比較する。セカンドオピニオン評価は母集団・判定入力のハッシュを残し、条件順を回して偏りを抑える。採点時の独立した根拠と発見可能性、重複した正解添字を検査する。本体と共通の応答解析に加え、既知の問いを使うprobeを別途用意している。精度や速度の測定結果は今回取得していない。

実装修正、テスト・型チェック・lint、実VSCode・外部CLI連携の検証は未実施。
